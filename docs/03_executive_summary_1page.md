# Executive Summary: KR-FinBert MLOps 서빙 시스템

## 핵심 전략

**목표**: 한국어 금융 감성 분석 모델(KR-FinBert-SC)을 **전담 운영 인력 없이** 가용성 **99.5% 이상**으로 서비스하는 완전 자동화 시스템 구축.

---

## 아키텍처 요약

| 구성요소 | 선택 기술 | 핵심 이유 |
|----------|----------|-----------|
| 서빙 API | FastAPI + Uvicorn | 비동기 I/O, 자동 문서화, 러닝 커브 최소 |
| 추론 엔진 | PyTorch CPU | 모델 호환성 100%, 변환 불필요 |
| 컨테이너 | Docker + K8s | 자동 스케일링, 자동 복구, Zero Downtime 배포 |
| CI/CD | GitHub Actions | 코드 Push → 테스트 → 빌드 → 배포 완전 자동화 |
| 모니터링 | Prometheus + Grafana + Loki | 외부 SaaS 없이 자체 구축, 오픈소스 |

---

## 성능 및 SLA

| 지표 | 수치 |
|------|------|
| 단일 추론 지연 | 50-80ms (CPU) |
| 처리량 (3 Pod) | 36-60 req/s |
| 목표 가용성 | 99.5% (연 다운타임 ≤ 43.8h) |
| 자동 스케일링 | 2~6 Pods (CPU 60% 기준) |
| 모델 업데이트 배포 | ~10분 (CI/CD 자동) |

---

## 주요 트레이드오프

| 결정 | 선택 | 포기 | 근거 |
|------|------|------|------|
| 추론 엔진 | PyTorch (운영 단순) | ONNX (2x 성능) | 월 1~2회 업데이트 시 변환 파이프라인 부담 |
| 로그 시스템 | Loki (경량) | ELK (전문 검색) | 5명 팀의 운영 역량 고려 |
| 스케일링 | CPU HPA | GPU 추론 | 현재 트래픽 수준에서 비용 효율 |
| 모델 배포 | 이미지 내장 | 외부 스토리지 | 네트워크 의존성 제거, 에어갭 대응 |

---

## 비용 효과

- **인프라**: CPU 서버 2-3대로 운영 가능 (GPU 불필요)
- **운영 인력**: 0명 (완전 자동화, 알림 기반 대응)
- **모니터링**: 오픈소스 (Prometheus + Grafana + Loki, 라이선스 비용 $0)
- **CI/CD**: GitHub Actions (Public Repo 무료, Private 2,000분/월)

## 리스크 및 완화

| 리스크 | 영향 | 완화 방안 |
|--------|------|-----------|
| 모델 크기 증가 | 추론 지연 증가 | ONNX 전환 또는 모델 경량화 |
| 트래픽 급증 | 응답 지연 | HPA + 큐잉 시스템 도입 |
| 단일 장애점 | 서비스 중단 | Multi-Pod + Node Anti-Affinity |
| 보안 취약점 | 데이터 유출 | 비루트 실행 + 이미지 스캔 + API 인증 |
